# 性能测试与改进记录

这份记录用于复现 XHS Clipper 的 OCR 压力测试。测试在 Windows 10、Chrome 151、PP-OCRv6 Tiny、WASM 四线程环境完成。数字反映这台机器和固定输入，不能直接当作所有设备的速度承诺。

## 真实 OCR 基准

固定输入是一张 960 × 1280 的图，共识别 29 行文字。每组先预热一轮，再连续运行 12 轮。

| 指标 | 改进前 | 改进后 |
| --- | ---: | ---: |
| 冷启动 | 325.4 ms | 328.0 ms |
| 平均单轮耗时 | 498.8 ms | 501.3 ms |
| P50 | 497.3 ms | 499.7 ms |
| P95 | 520.3 ms | 526.7 ms |
| 后段与前段耗时比 | 0.97 | 0.99 |
| 失败次数 | 0 | 0 |
| 测试前后总内存变化 | +25 KB | -290 KB |

显式释放 ONNX Tensor 后，吞吐没有明显变化，12 轮内也没有速度衰减。前后差异在普通运行波动范围内。测试结束后的内存没有净增长，说明资源能够回收。

同一套脚本在最终验收时再次运行，12 轮全部成功，平均耗时 684.1 ms，前段平均 682.3 ms，后段平均 671.6 ms，总内存净变化约 5 KB。绝对耗时会随机器负载变化，是否随轮次变慢应以前后窗口的趋势为准。

## 大任务状态基准

状态测试模拟 80 张图片，每张生成 80 行 OCR 结果。它覆盖进度通知、状态复制、持久化序列化和 Markdown 重建。这个规模高于小红书普通单篇笔记，用来放大随任务增长的开销。

| 指标 | 改进前 | 改进后 |
| --- | ---: | ---: |
| 累计处理耗时 | 8,586.77 ms | 229.95 ms |
| 前 10 张平均开销 | 14.65 ms | 0.40 ms |
| 后 10 张平均开销 | 194.20 ms | 5.30 ms |
| 最终状态大小 | 1,183,503 B | 359,343 B |

累计处理时间减少 97.3%，最终状态缩小 69.6%。后段仍然比前段慢，因为 Markdown 内容会随识别结果增长，不过单次开销已控制在 6 ms 内。

## 程序调整

- OCR 文字整理完成后，状态只保留整理过的文本，不再长期保存每行四边形坐标。
- 每张图开始时只发送轻量进度补丁，不再复制和持久化整份历史结果。
- 长图按块读取为 `ImageData`，省掉 PNG 重编码和再次解码。
- 每次推理后主动释放 ONNX 输入与输出 Tensor。
- 压力测试给大任务开销设置回归阈值。

## 复测

```bash
pnpm benchmark:job
pnpm benchmark:ocr
```

第二条命令会自动构建 `.benchmark-dist`、启动临时服务器、运行 Chrome 并关闭服务器，不会把基准页加入扩展安装包。Chrome 不在默认路径时，通过 `CHROME_PATH` 指定可执行文件。
